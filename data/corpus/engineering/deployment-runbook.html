Deployment Runbook

This runbook describes how services are deployed to production at Lumora Labs using the lumora CLI and Argo CD.

Deployment windows

Production deploys are allowed Monday to Thursday, 09:00–16:00 UTC. Friday deploys need approval from the Engineering Manager on duty. Deploys are frozen during recharge week (December 24 – January 1) except for SEV1 fixes.

Steps

  • Merge the pull request to main; CI builds and pushes the container image.
  • Run lumora deploy start <service> --env staging and wait for smoke tests to pass.
  • Promote with lumora deploy promote <service> --env production. Traffic shifts as a canary: 5%, then 25%, then 100% over 30 minutes.
  • Watch the service dashboard in Grafana. The canary auto-rolls back if the error rate goes above 1% or p99 latency doubles.

Rollback

To roll back manually, run lumora deploy rollback <service>. Rollback restores the previous image within 2 minutes. Always post in #deploys when you roll back.

Database migrations

Migrations run as a separate job before the deploy. Indexes on tables with more than 1 million rows must use CREATE INDEX CONCURRENTLY. Destructive migrations (dropping columns or tables) need a two-step deploy: first stop using the column, then drop it in a later release.
